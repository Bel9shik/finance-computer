# iPhone: сборка, проверка и установка

Если нужна установка **без Mac, Apple Developer и еженедельной переподписи**, используй [PWA-версию и её инструкцию](PWA.md). Ниже описана нативная сборка через Xcode.

Статус на 23 октября 2026: подготовлены настройки сборки для iOS 17+, исправлено отображение имён файлов из iOS, добавлены отступы для безопасной области экрана и удобные размеры полей и кнопок на телефоне. **Готового проверенного iOS-релиза и подписанного IPA пока нет.** На текущем Mac отсутствуют полный Xcode, iOS SDK, симулятор и сертификаты подписи. Генерация Xcode-проекта ещё не завершена.

Текущая версия исходников указана в `package.json`. Общие алгоритмы и интерфейс проверяются отдельно от нативного приложения: успешные тесты на Mac не подтверждают работу системных диалогов или сохранение на iPhone.

## Установка на свой iPhone через Mac

1. Установи полный **Xcode** из Mac App Store. Открой его, заверши первоначальную настройку и установи компоненты iOS и iOS Simulator. В **Xcode → Settings → Locations → Command Line Tools** выбери установленный Xcode. Версия Xcode должна поддерживать iOS твоего телефона.
2. В **Xcode → Settings → Apple Accounts** (в некоторых версиях — Accounts) добавь свой Apple Account. Для своего телефона достаточно бесплатной Personal Team. У такой подписи срок действия 7 дней, после чего приложение нужно снова собрать и установить. [Ограничения Personal Team у Apple](https://developer.apple.com/help/account/basics/about-your-developer-account).
3. Подключи iPhone кабелем, разблокируй и подтверди доверие Mac. После начала сопряжения с Xcode включи на iPhone **Настройки → Конфиденциальность и безопасность → Режим разработчика** и подтверди включение после перезагрузки. [Инструкция Apple](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device).
4. В Терминале подготовь инструменты и проект:

   ```sh
   cd cross-platform
   xcodebuild -version
   xcrun --sdk iphoneos --show-sdk-path
   brew install xcodegen cocoapods
   npm ci
   npm run ios:init
   npm run tauri -- icon src-tauri/icons/icon.svg --ios-color '#ffffff'
   npm run ios -- --open
   ```

   Первичная настройка загружает зависимости. Обёртка использует Rust из `../build/toolchain`, если он есть; на другом Mac предварительно нужен Rust через rustup. `ios:init` устанавливает iOS-цели Rust и генерирует проект в `src-tauri/gen/apple`. Требования к окружению приведены в [документации Tauri](https://v2.tauri.app/start/prerequisites/).

5. В открывшемся Xcode выбери iOS target → **Signing & Capabilities** → **Automatically manage signing** → свою Team. Если Tauri попросит Team ID, укажи идентификатор своей команды в переменной `APPLE_DEVELOPMENT_TEAM` и повтори команду открытия. Не используй чужой или выдуманный Team ID.
6. Выбери подключённый iPhone как устройство запуска. В **Product → Scheme → Edit Scheme → Run → Info** выбери **Build Configuration: Release**, затем **Product → Run**. Оставь команду `npm run ios -- --open` работающей в Терминале, пока Xcode собирает приложение: она предоставляет Xcode параметры сборки Tauri. Этот режим использует встроенный интерфейс из `dist`, сервер Vite для работы приложения не требуется. [Открытие release-сборки в Xcode](https://v2.tauri.app/distribute/app-store/).
7. Если iOS попросит довериться подписи разработчика, выполни указанные телефоном действия в **Настройки → Основные → VPN и управление устройством**. После успешного запуска отключи кабель и проверь приложение по списку ниже.

Если Apple сообщает, что Bundle Identifier уже занят, задай собственный уникальный `identifier` в `src-tauri/tauri.ios.conf.json` и повтори подготовку. После первой установки сохраняй этот идентификатор и ту же Team для обновлений. Не удаляй приложение ради переподписи: удаление удаляет его локальную базу. Перед переустановкой сохраняй копию через приложение.

## Перенос данных с Mac

В Mac-приложении нажми **Сохранить копию**, передай JSON на iPhone, затем в iPhone-приложении нажми **Загрузить копию** и выбери файл. Загрузка заменяет текущую базу после подтверждения; это не синхронизация. Для переноса только правил и имён используй **Импорт → Экспортировать настройки / Импортировать настройки**.

Приложение работает с локальными файлами. Если нужен полностью локальный экспорт, выбирай **На моём iPhone**: файлы из iCloud Drive загружает и синхронизирует iOS. Резервная копия содержит финансовые данные и реквизиты в открытом виде.

## Проверка перед выпуском

На этом Mac выполнены:

- 29 тестов TypeScript: точные суммы, типы операций, пресеты, дубли, PDF/XLSX, сверка итогов, повреждённые файлы, копии, настройки, отмена диалогов и ошибки файловых операций. В тестах файловых диалогов используется подмена IPC, а не настоящий iOS picker.
- Сборка production-интерфейса и проверка TypeScript.
- 2 Rust-теста: атомарная запись с обязательной резервной копией и запрет внешней навигации.
- Сценарии в macOS WebKit: графики, сортировка, редактор операции, импорт PDF/XLSX через Worker, русские имена из `file://`, импорт/экспорт настроек и отмена. Прогон на размерах телефона и настольного окна, в светлой и тёмной теме. Файловые диалоги и хранилище в этом стенде подменены; используются синтетические данные.

Повторить общие проверки из `cross-platform`:

```sh
python3 ../Tests/make_fixtures.py
npm test
npm run build
bash scripts/test-webview.sh 375 667
bash scripts/test-webview.sh 390 844
bash scripts/test-webview.sh 844 390 dark
bash scripts/test-webview.sh 1250 880
```

После установки Xcode нужно собрать и запустить приложение в iOS Simulator и на физическом iPhone. Ни один пункт ниже пока не подтверждён на iOS:

- Чистый запуск без сети, все пять разделов, портретная и альбомная ориентация, вырез экрана, светлая/тёмная тема, прокрутка длинных таблиц и открытых диалогов. Проверить на минимальной заявленной iOS 17 и актуальной iOS.
- Импорт нескольких PDF/XLSX из «Файлов», включая русские имена. Проверить суммы и историю импорта, повторный импорт, отказ от повреждённого файла, отмену выбора. При выборе облачного файла отдельно проверить его загрузку системой.
- Изменение категории и типа, индивидуальные исключения, группы и пресеты, свои телефоны, имена людей. Проверить ввод экранной клавиатурой и доступность кнопок при открытой клавиатуре.
- Полностью закрыть приложение и запустить снова: операции, настройки и исправления должны сохраниться. Повторить после блокировки телефона и возврата из фона.
- Экспортировать копию в «Файлы», проверить, что файл не пустой, открыть его на Mac и восстановить в тестовой базе. На iOS экспорт использует механизм системного переноса файла, поэтому реальный экспорт особенно важно проверить отдельно.
- Экспортировать и импортировать настройки, проверить предварительный просмотр и оба варианта приоритета. Убедиться, что отмена не меняет базу, а индивидуальные исправления сохраняются.
- На тестовых данных проверить **Начать заново** и восстановление копии; обновление поверх установленного приложения не должно терять данные. Проверить работу без сети после отключения кабеля и остановки команды сборки на Mac.

Workflow `.github/workflows/ios.yml` запускается вручную и предназначен для компиляции iPhone-архива и приложения симулятора без подписи. Он также запускает общие тесты. **Этот workflow ещё не запускался**, не выполняет тесты в iOS Simulator и не публикует приложение. Артефакт `finance-ios-unsigned-unverified` нельзя установить на обычный iPhone без дальнейшей подписи.

## Установка через TestFlight

Этот путь требует Apple Developer Program и доступ к App Store Connect. После проверки на устройстве: зарегистрируй приложение с тем же Bundle Identifier, в Xcode выполни **Product → Archive**, затем в Organizer выбери **Distribute App → App Store Connect → Upload**. После обработки сборки добавь тестировщиков на вкладке TestFlight; для внешнего тестирования может потребоваться проверка Apple. Пользователь устанавливает TestFlight из App Store, открывает приглашение и нажимает **Установить**. [Распространение через TestFlight](https://developer.apple.com/testflight/).

Сейчас сборка в App Store Connect не загружена, приглашения TestFlight нет. Публиковать её до проверки нативных сценариев выше нельзя считать завершённым выпуском.
